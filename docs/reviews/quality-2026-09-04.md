## 指摘事項

### Q1 / P1: 書き出し成功後のゲームが起動しない【実行再現】

根拠: `src/LamaPon/Editor/GameExporter.cpp:845`、`:878`、`src/LamaPon/Scripting/GameModuleHost.cpp:346`。

書き出し前にはModuleがRuntimeより新しいことを確認する。しかし書き出し中に `EmbedArchiveKey()` がコピー先Runtime DLLを書き換え、更新日時が新しくなる。Moduleのコピーは元の更新日時を保つため、配布先ではModuleがRuntimeより古く見える。起動時の互換性ガードがこれを拒否する。

今回の実測例（UTC）:

```text
Runtime DLL: 2026-09-04 04:18:24
Module DLL:  2026-09-04 04:17:30
export: ok=true, gameModuleIncluded=true
game: exit=1, Game Module is older than this engine build
```

**修正案:** 書き出し時のデータ埋め込みをABI変更と誤認しないようにする。短期対策ではコピー元Runtimeの更新日時を適切に保ち、長期的にはビルド識別子・ABI契約で互換性を判断する。書き出したEXEを実際に起動するテストを追加し、ファイル存在やJSON成功だけでは完了にしない。

### Q2 / P1: OnDestroyの例外でScriptの解放が抜ける【実行再現】

根拠: `src/LamaPon/Scripting/Script.h:857`、`src/LamaPon/Components/NativeScriptComponent.cpp:479`。

`ScriptBridge::Destroy()` は `OnDestroy()` の後に `delete` する。コールバックが例外を送出すると `delete` に到達しない。呼び出し元は例外を握りつぶしてポインターを捨てるため、デストラクターによる購読解除なども行われない。

例外を投げるScriptを用いた小さな確認プログラムでは、Destroy呼び出し後のデストラクター実行回数が **0** だった。確認後はプログラム自身が解放した。

**修正案:** 破棄開始時点でRAIIに所有権を移し、ユーザーの終了処理が失敗しても解放を保証する。終了処理のエラーも診断へ残す。OnDestroy失敗後の解放・購読解除を回帰テストにする。

### Q3 / P1: WebInputを破棄してもブラウザーのコールバックが残る【静的確認】

根拠: `src/LamaPon/Web/WebInput.cpp:16`、`:31`。

初期化時にキー、タッチ、マウスなどのコールバックへ `m_state` を渡すが、デストラクターは `delete m_state` だけ。登録解除がなく、破棄後に届くイベントが解放済み状態を参照する経路が残る。初期化が一部だけ成功した場合の巻き戻しもない。

**修正案:** 登録対象と成功した登録を保持し、破棄・初期化失敗時に解除してから状態を解放する。初期化→破棄→イベント、初期化失敗→再初期化をブラウザーで検証する。今回はEmscripten SDKが確認できず、ブラウザーでの再現は未実施。

### Q4 / P2: Scene::Clearの描画設定初期化漏れ【実行再現】

根拠: `src/LamaPon/Scene/Scene.cpp:3809`、`SceneSerialization.cpp:4568`。

TAA、SSR、Volumetric Lightを変更してから `Clear()` を呼んでも元の初期値に戻らない。次のJSONが項目を省略した場合、前シーンの設定を引き継ぎうる。3項目とも確認プログラムで再現した。

**修正案:** 描画設定と履歴状態をまとまりとして初期化し、通常ロード時に前の設定が残らないテストを追加する。意図して残すタグ等の設定とは分離する。

### Q5 / P2: EventBusの例外経路で配信中カウンターが戻らない【静的確認】

根拠: `src/LamaPon/Scene/EventBus.cpp:83`。

`handler(eventArgs)` が例外を投げると `--m_publishDepth` と無効エントリーの整理に到達しない。その後の解除・Clearが常に遅延処理となり、無効な配列要素が蓄積する。ReactiveのSubjectやSchedulerには同種の例外時後始末があるが、EventBusにはない。

**修正案:** 配信スコープのRAII、または例外時にも共通の終了処理を呼ぶ方式にする。再入、解除、例外の組み合わせをテストする。

### Q6 / P2: Editor / Scene / Graphics / CLIの責務集中【設計確認】

根拠と分割案は[前回の設計レビュー](architecture-2026-09-04.md)に記載。

`EditorLayer*.cpp` は39,011行、`DrawInspector()` は約10,300行。道路・車両・BGMツール、パッケージ処理等の状態まで同じクラスが所有する。Sceneも物理・描画・保存・GIを直接担当し、GraphicsDeviceは音声・入力も所有する。CLI Mainは9,697行。

**修正案:** CPPの分割に加え、状態の所有者を分ける。BGM等のパネル→Inspector→Scene描画/ベイク→物理/保存の順に移し、現在の公開APIを当面の委譲窓口にする。全private状態へアクセスできる巨大Contextへ置き換えるだけでは解決しない。

### Q7 / P2: WebテストがWindowsで失敗し、CIからも漏れている【実行・静的確認】

根拠: `tests/WebExportToolTests.py:201`、`:714`、`:754`、`:782`、`:852`、`.github/workflows/windows-ci.yml:55`、`CMakeLists.txt` のCTest登録。

34件中、5件が拡張子なしのPythonスクリプトを実行ファイルとして起動し、Windowsで `WinError 193`。1件はWindows形式のパス文字列を、スラッシュへ正規化したCMake出力と比較して失敗した。**この6件をWeb製品コードの不具合とは断定しない。** テスト補助処理にOS依存がある。

既存CIはC++のCTestのみで、このPythonスイートを実行しない。Debugも現在のCIでは構築しない。

**修正案:** 偽変換器はPythonを明示して実行できる形または適切なプロセスmockにする。パスを正規化して比較し、PythonテストをWindows CIへ登録する。Webのコンパイル・ブラウザースモーク検証を別の必須経路として設ける。

### Q8 / P1: 配布物に第三者ライセンス文書が同梱されない【配布内容確認】

根拠: `THIRD_PARTY_NOTICES.md`、`CMakeLists.txt:1653`。

既存ZIPと新規のCMake install先の両方で、ライセンス・NOTICE名の独立ファイルはルートの `LICENSE` と `THIRD_PARTY_NOTICES.md` のみ。NOTICEが案内する次の原文ファイルが存在しない。

- `third_party/XAudio2Redist/LICENSE.txt`
- `third_party/cgltf/LICENSE.txt`
- `third_party/ufbx/LICENSE.txt`
- `third_party/stb/stb_vorbis.c` 内のライセンス原文

ソースツリーには第三者通知があるが、配布物から案内先を読めない。これは同梱内容の確認であり、法的判断や依存ライブラリ全体のライセンス監査ではない。

**修正案:** 配布用の `licenses/` 等へ依存ごとの原文をまとめて同梱し、NOTICEの参照先と対応させる。ゲームのエクスポート先も含めて同梱を検証する。

### Q9 / P2: 配布用SDKにWeb出力を実行する一式がない【配布内容確認】

根拠: `CMakeLists.txt:1629`、`:1640`、`docs/web-export.md:183`。

Webの説明を同梱する一方、ZIP / install先には `tools/export_web.py`、`cmake/LamaPonWeb.cmake`、Portable / Web RuntimeのCPPがない。CMakeはProjectGameModuleのツールとヘッダーを主に配る構成で、Webに必要な実装一式はソースツリー側に残る。

**修正案:** Web SDKを配布対象へ追加するか、Web出力にはソースの取得とEmscriptenの別途設定が必要とREADME・同梱文書で明示する。ソースツリー参照がない隔離インストールから出力できるかを確認する。

### Q10 / P2: 公開コメントとAPI契約が一致しない【静的確認】

根拠: `src/LamaPon/Graphics/RenderPipeline.h:39`、`src/LamaPon/Scene/EventBus.h:24`、`src/LamaPon/Scripting/Script.h:432`。

`RunDepthPrepass` の戻り値は構造体なのに真偽値と説明し、SSAO無効時の説明もSSRのための実行と一致しない。EventBusの購読自動解除は `Script::On()` 等による寿命管理が条件で、生の `Subscribe()` に一律に適用されない。

**修正案:** 所有者・解除責任・戻り値・例外・スレッド条件を説明する。日付や特定プロジェクトでの経緯は必要に応じて履歴へ移す。ただし、DLLをまたぐ状態や互換処理の理由など、再発防止に役立つ説明は残す。

### Q11 / P2: Runtime更新後のModule再リンクと失敗診断が不十分【実行・静的確認】

根拠: `CMakeLists.txt:647`、`tools/ProjectGameModule/CMakeLists.txt` の `LINK_DEPENDS`、`tests/GameModuleTests.cpp:48`。

既存Releaseフォルダーでは通常ビルドが成功しても、Runtimeより古いサンプルModuleが残り `GameModuleRegistration` が失敗した。新規Releaseビルドは39件すべて成功した。プロジェクト用ModuleにはRuntime DLLの明示的なリンク依存があるが、ルートのサンプルModuleにはない。

加えて `Require(host.Load(...), host.LastError().c_str())` は、Loadより先にLastErrorのポインターを得る評価順序があり、Loadによる文字列変更で診断が不正になる。実際の失敗ログは文字化けし、LoadとLastError取得を順番に行う確認プログラムでは「Moduleが古い」と読めた。

**修正案:** Runtime実装だけの更新でも必要なModuleを再リンクする。Load結果とエラー文字列取得を別ステートメントにし、失敗理由を安定して記録する。新規ビルドだけでなく増分ビルドも検証する。

### Q12 / P2: PortableのLoggerがメッセージをすべて捨てる【静的確認】

根拠: `src/LamaPon/Portable/include/LamaPon/LamaPon.h:88`、`tools/export_web.py:174`。

互換性検査ではLoggerがcoreの対応APIに含まれるが、Info / Warning / Errorの本体が空。ゲームからエラーを記録してもブラウザー側の診断へ届かない。

**修正案:** ブラウザーコンソールまたは診断チャネルへ接続する。未提供のままなら互換性レポートで明示する。

### Q13 / P3: 自作コードのコンパイラー警告が残っている【ビルド確認】

Debug / Releaseとも警告121件。第三者コード100件、本体2件、テスト19件。

本体は `ModelRendererComponent.cpp:2530` の未使用変数、`EditorLayerInspector.cpp:10832` のローカル変数隠蔽。テストには変数隠蔽と `[[nodiscard]]` の戻り値無視がある。

**修正案:** 自作コードの警告を解消し、変更箇所の警告を欠陥として扱うCONTRIBUTINGの基準と揃える。第三者コードの警告は自作コードと区別し、闇雲に修正・一括抑制しない。

## 修正の順序と完了条件

1. **配布ゲーム起動（Q1）、Script破棄（Q2）、Web入力寿命（Q3）、ライセンス同梱（Q8）**。再現手順を回帰テストにし、出荷の必須条件にする。
2. Scene / EventBus / 増分ビルド・診断（Q4、Q5、Q11）とWebのテスト・配布・ログ（Q7、Q9、Q12）を修正。
3. 実装とコメントを合わせ、自作コードの警告を解消（Q10、Q13）。
4. Q6の責務分割を、小さい変更と既存ゲームの回帰確認を挟んで進める。

構造改善の完了条件はファイル数や行数ではなく、各担当が自分の状態を所有し、限定した依存で検証できること。公開前の品質ゲートには、既存CTestに加えて**配布物からゲームを作り、その出力を起動すること**を含める。
