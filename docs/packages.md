# パッケージ

C++スクリプト、Prefab、アセットをパッケージとしてまとめ、エディターからプロジェクトへ導入できます。

[← ドキュメント一覧へ戻る](index.md)

## 使い方

1. エディターの「**拡張機能**」→「**パッケージを探す...**」でタブを
  開きます（開くと自動で公式パッケージの一覧を取得します）。
2. 左の一覧からパッケージを選び、右の説明を確認して
  「**インストール**」を押します。
3. ダウンロードと展開が終わると `assets/packages/<名前>/` に入り、
  **C++スクリプトを含む場合はGame Moduleが自動ビルド**されます。
  完了すれば「コンポーネントを追加」からすぐ使えます。

- 導入済みのパッケージには「導入済み」と表示され、新しい版があれば
  「**更新する**」ボタンに変わります。
  「**削除**」でフォルダーごと取り除けます。
- パッケージは**ソースコードのまま**プロジェクトへ入るため、中の
  `.cpp` を開いてそのまま学習・改造できます。
  削除・改造してもエンジン本体には影響しません。

パッケージには有効化タイミングがあります。通常は「すぐに有効」ですが、
ネイティブDLLや描画バックエンドを含むものは「再起動後に有効」、生成物にも
影響するものは「再起動・再ビルド後に有効」と表示されます。この場合は実行中の
DLLを差し替えず、インストール・更新・削除のあとに再起動する安全な設計です。

作者は`package.json`と一覧へ`activation`を指定できます。値は`Immediate`、
`Restart`、`RestartAndRebuild`です。省略した既存パッケージと不明な値は、互換性を
保つため`Immediate`として扱います。

## 公式パッケージ

| パッケージ | 内容 |
|---|---|
| **Easing & Tween**（`easing-tween`） | 動きに緩急をつけるイージング関数28種と、位置・回転・拡縮を時間をかけて動かす「Tween」コンポーネント。`Easing.h`をincludeすれば自分のScriptからも使えます |
| **Discord Rich Presence (Social SDK)**（`discord-presence-sdk`） | [Discord Rich Presence](online-services.md#discord-rich-presence)を実際にDiscordへ表示するためのアダプター。ライセンス上SDK本体は同梱できないので、Discordから入手して`sdk/`へ置く形です（手順はパッケージのREADME）。Discordログインとは無関係で、ログインしなくても使えます |

導入すると`assets/packages/<名前>/`へ入り、Game Moduleが自動ビルドされて「コンポーネントを追加」から使えるようになります。
中身は`.cpp`のままなので、開いて読んだり改造したりできます。

## 対応エンジンバージョン

各パッケージは必要な最低エンジンバージョンを宣言しています。
お使いのエンジンが古い場合はインストールボタンが無効になり、エンジンの更新案内が表示されます（LamaPon Hubを起動すると新しいバージョンのダウンロードバナーが出ます）。

## オフラインのとき

- 公式一覧と配布 ZIP はリポジトリの `packages/` で管理します。
  リポジトリは公開済みなので、エディターから一覧と ZIP をそのまま取得できます
  （一覧は `main` ブランチの `packages/index.json` を読みます）。
- 一覧の取得と新規インストールにはインターネット接続が必要です。
  つながらない場合はその旨を表示し、「再読み込み」で再試行できます。
- インストール済みパッケージのファイルは、オフラインでも利用できます。

## 自分でパッケージを作る

作った機能（スクリプト・Prefab・画像など）を、他の人がワンクリックで導入できる形にまとめられます。

1. `assets/packages/<パッケージ名>/` フォルダーを作り、配りたい
  ファイルを入れます（パッケージ名は英小文字・数字・`-`・`_`）。
  **普通のプロジェクトの一部として動作確認できます。**
  外部SDKを使う場合は
  [ネイティブライブラリを含むパッケージ](#ネイティブライブラリを含むパッケージ)
  も参照してください。
2. 「**拡張機能**」→「**パッケージを作成...**」で名前・表示名・説明・
  作者・バージョンを入力し、「Zipを作成」を押します。
3. `dist/packages/<名前>-<バージョン>.zip` ができます。あわせて
  `package.json`（パッケージの情報）がフォルダー内へ生成されます。

## ネイティブライブラリを含むパッケージ

外部SDK（Discordの Social SDK、Steamworks など）をパッケージから
使えます。`package.json`へ`native`を書くと、Game Moduleのビルドと
ゲームの書き出しへ自動で反映されます。

```json
{
  "name": "my-sdk",
  "displayName": "My SDK",
  "version": "1.0.0",
  "minimumEngineVersion": "0.1.0",

  "native": {
    "includeDirectories": [ "sdk/include" ],
    "libraries":          [ "sdk/lib/my_sdk.lib" ],
    "runtimeFiles":       [ "sdk/bin/my_sdk.dll" ],
    "defines":            [ "MY_SDK_ENABLED" ]
  }
}
```

| キー | 反映先 |
|---|---|
| `includeDirectories` | Game Moduleのインクルードパス |
| `libraries` | Game Moduleへリンクする`.lib` |
| `runtimeFiles` | 編集中のプレイと書き出したゲームへ同梱する`.dll` |
| `defines` | Game Moduleのコンパイル時マクロ |

パスはすべて**パッケージフォルダーからの相対パス**です。4つとも
省略できます。`native`が無いパッケージは今までどおり動きます。

### 置き場所

SDKのファイルはパッケージフォルダーの中へ置きます。

```text
assets/packages/my-sdk/
├─ package.json
├─ MySdkAdapter.cpp     ← Game Moduleへ組み込まれるC++
└─ sdk/
   ├─ include/          ← includeDirectories
   ├─ lib/my_sdk.lib    ← libraries
   └─ bin/my_sdk.dll    ← runtimeFiles
```

`runtimeFiles`のDLLは、エディターでのプレイ時はここから直接読まれ、
書き出し時は実行ファイルの隣へコピーされます。作者が手で配る必要は
ありません。

### 再配布できないSDKを使う場合

多くの商用SDKは、単体での再配布や改変を禁止しています。その場合は
**SDK本体をパッケージへ入れず**、`sdk/`フォルダーを空のまま配って
ください。利用者がSDKを自分でダウンロードして`sdk/`へ置く手順を、
パッケージのREADMEへ書きます。

ファイルが足りないままGame Moduleをビルドすると、リンカーのエラー
ではなく次のような案内が出ます。

```text
パッケージが必要とするネイティブライブラリが見つかりません。
パッケージのREADMEに従って配置してください:
  - my-sdk: .../assets/packages/my-sdk/sdk/lib/my_sdk.lib
```

公式パッケージの`discord-presence-sdk`がこの形です。実物を見たい
ときは`packages/src/discord-presence-sdk/`を読んでください。

### 書けないこと

`native`で指定できるのは上の4項目だけです。コンパイルオプションや
リンクオプションを直接渡すことはできません。ダウンロードした
パッケージがビルドコマンドを書き換えられると、ソースを読んだだけでは
分からない挙動を持ち込めてしまうためです。

次のような指定はインストール時に拒否されます。

- `..`や絶対パス（`C:\...`、`/usr/...`、`\\server\...`）など、
  パッケージフォルダーの外を指すパス
- `libraries`に`.lib`以外、`runtimeFiles`に`.dll`以外
- `compileOptions`のような未知のキー
- `NAME`／`NAME=VALUE`の形になっていない`defines`
- 1項目あたり32件を超える指定

また、`LamaPonRuntime.dll`や`msvcp140.dll`のようなエンジン自身の
DLLと同じ名前は同梱できません。複数のパッケージが同じ名前のDLLを
同梱しようとした場合も、書き出し時に止まります。

### パッケージを作り直しても消えません

`native`は手で書く項目ですが、「拡張機能」→「パッケージを作成...」で
`package.json`を作り直しても**そのまま引き継がれます**。
一覧用のJSONには含まれません（ビルド情報はZip内の`package.json`が
正本です）。

同様に、将来の任意描画バックエンドが使う`graphicsBackend`宣言も、パッケージを
作り直したときに保持されます。これは一般スクリプト向けの設定ではありません。

## 作ったパッケージを配る

- **そのままZipを渡す**のが一番簡単です。受け取った人は
  「拡張機能」→「**Zipから読み込む...**」で導入できます。
- 一覧形式で公開したい場合は、ダイアログに表示されるJSONを自分の
  配布場所（GitHub等）の`index.json`へ追加します。
  **公式パッケージ一覧とは別管理**なので、自分のペースで公開・更新できます。

導入したパッケージのうち公式一覧に無いもの（自作・受け取り物）は、パッケージタブの「このプロジェクトのパッケージ（公式一覧外）」にまとめて表示され、そこから削除もできます。

## よくあるつまずき

- **一覧が空** — 公式パッケージの公開前はこの状態が正常です。
- **「エンジン vX 以降が必要です」と出る** — LamaPon Hubから新しい
  エンジンをダウンロードして入れ替えてください。
  プロジェクトはそのまま使えます。
- **インストール後にコンポーネントが見つからない** — C++の自動
  ビルドが走っています。
  Consoleにビルド完了が出るまで少し待って、「コンポーネントを追加」を開き直してください。
- **パッケージを改造したら更新で消えた** — 「更新する」「再インストール」は
  フォルダーを丸ごと置き換えます。
  ただし置き換えた旧版は`.lamapon/package-backups/<パッケージ名>/`へ**1世代だけ**退避されるので、改造したファイルはそこから取り出せます（次の更新で上書きされます）。
  改造して使い続ける場合は、ファイルを`assets/packages/`の外へコピーしてから編集するのが安全です。
  なお退避先が`assets/`の外にあるのは仕様です。
  パッケージのC++はゲームモジュールへ自動で組み込まれるため、`assets/`内へ旧版が残ると同じコンポーネントが二重に定義されてビルドが壊れます。
- **更新の途中で失敗した** — 置き換えは「旧版を退避 → 新版を入れる →
  失敗したら旧版を戻す」の順で行うので、途中で失敗してもパッケージが消えたり半端な状態になったりはしません。
  自動で戻せなかった場合も、旧版はエラーメッセージに出る退避先に無傷で残っています。
