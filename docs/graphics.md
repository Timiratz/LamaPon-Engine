# グラフィックス

3Dモデル、ライティング、Skybox、Fog、Bloom、Litマテリアル、Particle、
LOD、描画カリングの設定を説明します。

[← ドキュメント一覧へ戻る](index.md)

## 最初に設定する3項目

最初は次の3項目を設定すると、画面の見た目を確認しやすくなります。

1. **影をつける** — Hierarchyの「太陽光」（平行光源）を選び、Inspectorで
  影を有効にします。
  品質プリセットがLowだと影は無効なので、プロジェクト設定でMedium以上にします。
2. **空・霧・発光** — Inspectorの「シーン環境」でSkybox、Fog、Bloomを
  ONにします。
  外部テクスチャなしで空と遠景のなじみ、光のにじみが出ます。
3. **材質感** — MeshRendererのマテリアルで「粗さ」を下げると金属や
  プラスチックのような光沢に、上げるとマットな質感になります。
  `.dds`キューブマップをSkyboxへ設定すると、粗さに応じた正確な映り込み（IBL）になります。

## 3Dモデル

Asset BrowserとModelRendererは次のDirectXTK形式に対応しています。

- `.cmo`
- `.sdkmesh`
- `.vbo`
- `.gltf`
- `.glb`
- `.fbx`

FBXは中間形式へ変換せず、元の`.fbx`からメッシュ、マテリアル、スキン、アニメーションを直接読み込んで描画します。

GameObjectへModelRendererを追加し、Asset Browserでモデルを右クリックして「モデルを割り当て」を選ぶか、Inspectorへドラッグ＆ドロップします。

### FBXの静的パーツ自動結合

アニメーションを持たないFBXでは、インポート時にボーン（スキン）の付いていないパーツを同じマテリアルどうしで1つの頂点／インデックスバッファへ自動結合します。
DCCツールから、ボディパネル・ボルト・トリムなどが数百個の別パーツのまま書き出されていると、パーツ単位のドローコールと状態変更がCPU負荷の支配要因になるためです。

結合結果はConsoleの`FBX imported:`ログに`parts=717->15 (merged)`の形で出ます。
結合してもなおドローコールが64を超えるモデルには、DCCツール側でメッシュをまとめてから書き出すことを勧める警告を出します。
スキン付き、またはアニメーションを含むモデルは結合対象外で、従来どおりの描画経路を使います。

FBX側の単位設定が実寸と食い違っている場合は、Asset Browserで`.fbx`を選び、Inspectorの「インポートスケール」で補正できます（[エディター](editor.md)の「Model Asset Inspector」を参照）。

### インポートキャッシュ（2回目からの読み込みが速くなります）

FBX/glTFのインポート結果は`%LOCALAPPDATA%\LamaPon\model-cache`へ自動保存され、同じモデルの2回目以降の読み込みはパースと組み立てを飛ばしてファイルを読むだけになります。
静的パーツの自動結合の結果もキャッシュに含まれます。

- 鍵はモデルファイルの**中身**です。差し替えれば自動で作り直されます
- 外部の`.bin`・外部テクスチャ・`.meta`（インポートスケール）も一緒に
  照合するので、どれかを変えれば作り直されます
- フォルダーごと消しても、次の読み込みで作り直されるだけで害はありません

### モデルのマテリアル取り込み

glTF／FBXからは、モデルが持っている次のマテリアル情報を読み込みます。
読み込んだモデルは既定でLamaPon Lit（Cook-Torrance GGXのPBR）で描かれるため、マテリアル上書きを有効にしなくても法線マップとmetallicが効きます。

| 項目 | glTF | FBX |
| --- | --- | --- |
| ベースカラー | `baseColorFactor` | `base_color` |
| アルベドテクスチャ | `baseColorTexture` | `base_color`のテクスチャ |
| 法線マップ | `normalTexture` | `pbr.normal_map` |
| 粗さ | `roughnessFactor` | `pbr.roughness` |
| metallic | `metallicFactor` | `pbr.metalness` |
| 粗さマップ | `metallicRoughnessTexture`の`G` | `pbr.roughness`のテクスチャ |
| metallicマップ | `metallicRoughnessTexture`の`B` | `pbr.metalness`のテクスチャ |
| 遮蔽（AO）マップ | `occlusionTexture`の`R`（`strength`込み） | `pbr.ambient_occlusion`のテクスチャ |
| 発光色 | `emissiveFactor`（`KHR_materials_emissive_strength`込み） | `pbr.emission_color`×`pbr.emission_factor` |
| 発光マップ | `emissiveTexture` | `pbr.emission_color`のテクスチャ |
| 不透明度 | `alphaMode` | `pbr.opacity` |

粗さ・metallicマップは係数へ掛け算されます（glTF仕様と同じ扱い）。
glTFでは`metallicRoughnessTexture`の1枚にG＝粗さ、B＝metallicが入っており、FBXでは別画像ですが、どちらもグレースケールなら同じ読み方で一致します。

**遮蔽マップは環境光／IBLにだけ掛かります。** 直接光にも掛けると、影の中が二重に暗くなって汚れて見えるためです（glTF仕様も同じ扱いです）。

発光（emissive）はライティングと無関係に加算されるので、**影の中でも暗いシーンでも光ります。** 看板・ネオン・モニター・魔法エフェクトなどに使えます。
発光を1より強くすると（glTFの`KHR_materials_emissive_strength`、または発光色を大きくする）Bloomがそのまま滲みを付けるので、光っている感じが出ます。
Bloomは「シーン環境 → Bloom」で有効にしてください。
Fogは発光のあとに掛かるため、遠くのネオンは霧に沈みます。

Inspectorの「マテリアルを上書き」を有効にすると、モデル自身の材質の代わりにModelRendererのLitMaterialが使われます。
上書き中はアルベドと法線マップもLitMaterial側の設定が優先されます。

#### ポリゴンの面が見えるようになった場合

LamaPon Litは**ピクセル単位**でライティングを計算します。
従来のDirectXTK描画は頂点単位（Gouraud）で、頂点で求めた明るさを面の中で補間していたため、面ごとの陰影差が塗りつぶされて滑らかに見えていました。

そのため、**分割の粗いモデルは面の境目が見えるようになります。**これは計算が正確になった結果で、不具合ではありません。
滑らかに見せたい場合は次のどちらかで対応してください。

- DCCツール側で法線を平滑化（スムーズシェーディング）して書き出し直す。
  面ごとに法線が分かれていると、ピクセル単位では段差として出ます
- そのモデルだけ下の「従来のDirectXTK描画を使う」をオンにする

#### 従来のDirectXTK描画へ戻す

Inspectorの「従来のDirectXTK描画を使う」をオンにすると、そのModelRendererだけ以前の描画（DirectXTK `SkinnedEffect`のBlinn-Phong）に戻ります。
法線マップとmetallicは効かなくなります。
旧バージョンと同じ見た目を保ちたいモデルにだけ使ってください。
現在どちらで描かれているかはInspectorの「描画経路」に出ます。

シーンJSONの`useLegacyShading`が未指定のときはLamaPon Litとして読み込むため、既存シーンをそのまま開くだけで新しい描画に切り替わります。

## ライティング方針

Scene共通の環境光とDirectional／Point／Spot Lightコンポーネントを実装済みです。

- Inspectorの「シーン環境」で環境光カラーと強度を編集
- GameObjectへ「平行光源」「ポイントライト」「スポットライト」を追加
- Transformの回転から照射方向を計算
- ライト色、強度、範囲、スポット内側／外側角度をInspectorで編集
- ポイント／スポットはクラスタライトカリング（Forward+）で最大256灯
  （下の「ライト数の考え方」を参照）
- ライト設定と環境光を`.scene.json`へ保存
- Scene Viewに方向矢印、範囲球、スポットコーンのギズモを表示
- Directional Lightごとの影、描画距離、濃さ、深度／法線バイアス設定
- 1～4分割のカスケードシャドウと分割バランス設定

新規シーンにはメインカメラと「太陽光」が自動作成されます。
既存シーンにもGameObjectの「コンポーネントを追加」から各ライトを追加できます。
環境光は3D描画だけへ適用され、SpriteRenderer／TextRendererなどの2D描画には影響しません。

MeshRendererは`assets/shaders/LamaPonLit.hlsl`を使い、ピクセル単位のLambert＋Blinnライティング、距離の二次減衰、スポットコーン減衰を計算します。
マテリアル上書きを有効にした互換性のある静的ModelRendererも同じシェーダーを使うため、Point／Spot Lightをピクセル単位で計算します。
DirectXTKへフォールバックしたモデルでは、各モデル中心で最も強い方向のライトへ近似します。
近似に使える灯数はエフェクトの種類で決まり、DGSLEffect（CMOのカスタムマテリアルなど）は4灯、BasicEffectやSkinnedEffectなどそれ以外のDirectXTKエフェクトは3灯までです（DirectXTKの仕様上の上限）。

影を有効にした最初のDirectional Lightは、カメラの視錐台を最大4範囲へ分割し、各範囲を2048×2048のTexture2DArrayへ毎フレーム描画します。
近景ほど狭い範囲へ解像度を集中できるため、単一ShadowMapより遠距離と精細さを両立できます。
Inspectorではカスケード数と、均等分割／近景重視を調整する分割バランスを設定できます。

各正投影範囲はShadowMapのテクセル単位へスナップされ、カメラを少し動かしたときの影の揺れを抑えます。
Litシェーダーではカメラ深度からカスケードを選び、境界付近10%を次のカスケードとブレンドして切り替え線を抑えます。
影の輪郭は3×3のPCF（比較サンプラーの2×2と合わせて実質4×4相当）で柔らかくなり、スポット影も3×3、ポイント影は接平面5タップのPCFです。
深度バイアス／法線バイアスでシャドウアクネと浮きを調整できます。
MeshRendererとModelRendererは影を落とします。
共通Litシェーダーで描画されるMeshRendererと静的ModelRendererは影を受けます。

### 描画方式（Rendering Path）

プロジェクト設定の「グラフィックス」で**描画方式**を選べます。
描画方式によってライトの計算方法が変わります。
品質プリセットとは独立していて、プリセットを切り替えても引き継がれます。

| 描画方式 | 1回の描画で使えるライト | 向いている場面 |
|---|---|---|
| **Forward+**（既定） | ポイント＋スポット合計256灯 | ライトを多く置くシーン |
| Forward | 品質設定のポイント／スポット上限まで（High=12/4） | ライトが少ないシーン、非力な環境 |

Forwardを選ぶとクラスタの前計算（Compute Shaderのディスパッチ）ごと省くので、ライトが数灯しかないシーンではそのぶん軽くなります。
逆にライトを多く置いたシーンでForwardにすると、上限を超えたライトが**消えます**（暗くなるだけで破綻はしません）。

どちらで描いているかは、エディターの「パフォーマンス」タブの「描画」欄に出ます。

### ライト数の考え方（Forward+）

標準のLitシェーダー（MeshRenderer／ModelRenderer）は、Forward+のとき**クラスタライトカリング**で描画します。
視錐台を16×9×24の格子（クラスタ）に切り、Compute Shaderが「そのクラスタに届くライトの番号表」を毎フレーム作るので、ピクセルごとの計算量は「近くにあるライトの数」で決まります。
シーン全体では**ポイント＋スポット合計256灯**まで置けます。

- 品質設定のポイント／スポット上限（High=12/4など）は、**従来の16灯経路**
  （下記）にだけ効きます。
  Forward+のLitシェーダーのオブジェクトには影響しません
- 1クラスタに同時に届くライトは32灯まで。狭い場所に33灯以上重ねると
  超えた分は落ちます（暗くなるだけで破綻はしません）
- 正射影（2Dモード）のカメラでは、Forward+を選んでいても自動的に従来経路へ
  切り替わります

**従来の16灯経路が残る場所**: 自作Shader（`LAMAPON_PROPERTIES`で作ったカスタムマテリアル）とDirectXTKフォールバックのモデルは、従来どおり「シーン全体から先着N灯」の定数バッファを読みます。
自作Shaderのオブジェクトが多灯シーンで暗くなる場合はこれが原因です。

2D描画は基本的に非ライティングのまま維持し、必要になった段階で2D Lightを別系統として追加します。

## Skybox、Fog、Bloom、Screen Space Lens Flare

Inspectorの「シーン環境」から、シーン全体の空・霧・発光表現を設定できます。

- Skybox：上空、地平線、下側の3色と明るさを持つプロシージャル空
- Fog：色、開始距離、終了距離、密度を指定する距離フォグ
- Bloom：しきい値、強度、広がりを指定する全画面ポストエフェクト
- 画面アウトライン：シーン深度からシルエットと形状の折れ目を検出して線を重ねる全画面ポストエフェクト
- Screen Space Lens Flare：高輝度部分から光学ゴースト、ハロー、放射状の
  ストリークを作る全画面ポストエフェクト
- 被写界深度 (DoF)：ピントの合う距離から離れたものをぼかす全画面
  ポストエフェクト（[詳細](#被写界深度dof)）
- モーションブラー：カメラが動いたぶんだけ絵を伸ばす全画面ポストエフェクト
  （[詳細](#モーションブラーカメラの動きによるブレ)）
- 自動露出：画面の明るさを測って露出を上下させる明順応・暗順応
  （[詳細](#自動露出明順応暗順応)）

Skyboxはカメラの向きから背景を生成するため、外部テクスチャなしで利用できます。
`.dds`キューブマップを指定するとIBL（環境反射・環境拡散）が有効になり、初回に一度だけGPUでGGX事前畳み込み（粗さ別ミップのスペキュラキューブ）とコサイン畳み込みの放射照度キューブを生成します。
これにより、粗いマテリアルはぼけた映り込み、滑らかなマテリアルは鮮明な映り込みと、粗さに正確な環境反射になります（BRDF項はLUT不要の解析近似で評価）。
FogはLamaPonLitシェーダーに加え、DirectXTK標準Effectへフォールバックしたモデルにも適用されます。
BloomはScene View、Game View、エディターなしの通常ゲーム描画に対応し、明るいライトや加算パーティクルの周囲へ柔らかな発光を加えます。
Screen Space Lens FlareはBloomとは別に、Inspectorの「シーン環境」から有効化できます。
既定では無効です。
高輝度部分を光源として扱うため、発光マテリアルや強いライトが画面内にあるときに効果が分かりやすくなります。
プロジェクトのグラフィック品質設定でも有効である必要があります（High以上のプリセットで有効）。

設定はシーンJSONの`environment.sky`、`environment.fog`、`environment.bloom`、`environment.screenSpaceLensFlare`へ保存されます。
Screen Space Lens Flareは既定で無効なので、InspectorのチェックボックスでBloomと個別に比較できます。

### 画面アウトライン

モデルごとに特殊なマテリアルを設定しなくても、シーン全体へ輪郭線を掛けられます。
Inspectorの「シーン環境 → 画面アウトライン」から有効にするか、コードから設定します。

```cpp
auto outline = scene.ScreenOutline();
outline.enabled = true;
outline.color = { 0.02f, 0.02f, 0.02f };
outline.intensity = 1.0f;       // 線の強さ
outline.thickness = 1.0f;       // 1〜4画素
outline.depthThreshold = 0.025f; // 奥行きの感度
outline.normalThreshold = 0.25f; // 面の折れ目の感度
scene.SetScreenOutlineSettings(outline);
```

- 深度からビュー空間法線を再構成するため、追加の法線バッファやMRTは必要ありません
- シルエットと形状の折れ目を検出します。マテリアルのノーマルマップにある細かな凹凸は対象にしません
- 3Dへだけ適用され、ポスト処理後に合成される2D／UIには掛かりません
- トーンマップ後、FXAA前に適用されます。線の色は画面の明るさに引きずられにくく、FXAAで階段も滑らかになります
- リフレクションプローブのベイク中は適用されません
- 設定はシーンJSONの`environment.screenOutline`へ保存されます

### 朝昼夜（ライトの回転で時間帯を変える）

シーン環境の**「朝昼夜」**を入れると、Directional Lightの向きだけで夜明けから日没までを表現できます。
入れると空の3色と環境光は太陽の高度から自動で決まり、上の色設定は使われません。
空には太陽そのものも描かれます。

**ライトのX回転が高度です。** -90度で真上（正午）、0度で地平線、+90度で真下（真夜中）。
スクリプトでX回転を進めれば、それがそのまま時間の流れになります。

```cpp
// 1分で1日が回る例
auto& transform = sun.GetTransform();
auto angles = transform.EulerAngles();
angles.x += DirectX::XM_2PI * LamaPon::Time::DeltaTime() / 60.0f;
transform.SetEulerAngles(angles);
```

- **夜の暗さは自動です。** 太陽が地平線の下へ回ると光は下から差すことになり、
  上を向いた面には当たらなくなります。
  ライトを消す処理は要りません。
- **夜も完全な黒にはしません。** 月明かり程度の青を環境光に残しています
  （真っ黒だと何も見えず、ゲームになりません）。
- **太陽の大きさ**は、そのライトの「見かけの大きさ」設定に従います（下記）。
- [水面の見本Shader](shaders.md)と組み合わせると、夕日が水面に伸びます。

### 太陽の見かけの大きさ

Directional Lightの**「見かけの大きさ（度）」**は、空に見えている光源の直径です。
既定は本物の太陽と同じ**0.53度**。

これは**つるつるした物のハイライトの大きさ**を決めます。
0にすると光源は数学的な点になり、磨いた金属や水面ではハイライトが1画素より小さくなって、消えたように見えます。
大きくすると曇り空のように光沢がぼんやり広がります。

粗い材質では効果がほとんど見えません。
材質のざらつきのほうが太陽の0.53度よりずっと広いためで、これは正しい挙動です。
効くのは磨かれた面だけです。

### レンズフレアの筋（ストリーク）

筋は**1/4解像度で3回に分けて**作ります。
1パスで長い筋を作ろうとするとタップの間隔が空いて点線になるため、「少し進めて書き戻す」を繰り返し、毎回タップ間隔を4倍に広げます。
12タップで画面を横切る連続した筋になります。

| 設定 | 効果 |
|---|---|
| 筋の強さ | 合成時の倍率。0で筋なし（3パスまるごと省略されます） |
| 筋の長さ | どこまで伸ばすか（画面比） |
| **筋の本数** | 1で横一本（アナモルフィック風）、2で十字、3以上で放射状 |
| **筋の角度** | 1本目の角度。本数ぶん半円を等分します（筋は両側へ伸びるため） |
| 色分散 | 筋の長さ方向に波長をずらします。中心が白く、外へ行くほど色が分かれます |

**筋を目立たせるには光源がHDRで十分明るいことが要ります。** 筋は光を長い距離へ広げる表現なので、元が明るくないと薄く伸びるだけになります。
発光マテリアル（Emissive）を強めに設定した小さな物体がいちばん映えます。

## Litマテリアル

MeshRendererとModelRendererは共通の`LitMaterial`を持ち、Inspectorから次を編集できます。

- ベースカラーとアルファ
- 粗さ
- metallic
- アルベドテクスチャ
- 法線マップ
- 法線強度
- 粗さマップ／metallicマップ（数値へ掛け算されます）
- 遮蔽（AO）マップと遮蔽の強さ（環境光／IBLにだけ掛かります）
- 発光マップと発光色（ライティングと無関係に加算。Bloomが滲ませます）

PBRマップと発光はInspectorの「PBRマップ（粗さ・金属度・遮蔽・発光）」を開くと編集できます。
各枠へ画像をドラッグ＆ドロップするか、Asset Browserで画像を選んで「選択画像を割り当て」を押します。
読み込みモデルが自分で持っているマップは自動で使われるので、こちらで指定する必要があるのは手置きのMeshRendererか、モデルのマップを差し替えたいときだけです。

Asset Browserで画像を右クリックし「画像を割り当て」を選ぶと、選択中のMeshRendererではアルベドへ、ModelRendererではマテリアル上書きを有効にしてアルベドへ割り当てられます。
Inspectorのアルベド欄／法線マップ欄へ画像をドラッグ＆ドロップするか、「選択画像をアルベドへ」「選択画像を法線へ」も使用できます。

マテリアル設定とテクスチャパスはシーンJSONへ保存されます。
画像ファイルやフォルダーの移動・改名では参照が自動更新され、削除時にはSpriteRenderer／ModelRendererと同様に参照元として警告されます。

Asset Browserのフォルダーまたは空白の右クリックメニューから`.material.json`を作成できます。
MeshRenderer／ModelRendererへドラッグするか、Materialの右クリックメニューから「Materialを割り当て」で共有Materialを設定します。
Inspectorでは次の操作が可能です。

MaterialをAsset Browserで単クリックすると専用Inspectorが開き、ベースカラー、粗さ、アルベド、法線マップ、Shader、カスタムパラメーターをまとめて編集できます。
「選択オブジェクトへ適用」で、選択中のMeshRenderer／ModelRendererへ直接割り当てられます。
ShaderはMaterial Inspectorおよび各Rendererの候補一覧から選択でき、標準Litへも戻せます。

- 「Materialへ保存」で現在の値を共有ファイルへ保存
- 「再読込」でディスク上の共有値へ戻す
- 「個別化」で現在値を保ったまま共有参照を解除

共有Materialを保存すると、同じシーン内でそのMaterialを参照する全Rendererへ即座に反映されます。
シーンJSONには共有Materialのパスとフォールバック用の現在値が保存されるため、既存シーンとの互換性も維持されます。

`LamaPonLit.hlsl`はGeometricPrimitiveのUVを使ってアルベドをサンプリングします。
法線マップ用の接線空間はピクセルシェーダー内の位置／UV微分から生成するため、プリミティブ頂点へ接線データを追加する必要はありません。
法線マップ未設定時は内部のフラット法線テクスチャを使用します。

### カスタムShader

書き方の解説とサンプルHLSLは[カスタムShaderガイド](shaders.md)にまとまっています（2Dスプライト用・画面全体ポストエフェクトもこちら）。

Asset Browserのフォルダー内で右クリックし「新規カスタムShader」を選ぶと、編集可能なHLSL雛形を作成できます。
HLSLをダブルクリックしてコードエディターで編集し、Mesh Renderer／Model RendererのInspectorへドラッグしてMaterialに設定します。
保存したHLSLは実行中も自動再コンパイルされ、失敗時はInspectorへエラーを表示しながら直前の正常なShader（未成功なら標準Lit）で描画を継続します。

カスタムShaderはShader Model 5.0の`VSMain`と`PSMain`を持ち、雛形と同じ`ObjectBuffer`レイアウトを使用します。
Inspectorの「カスタムShaderパラメーター」から`CustomParameters[0]`〜`CustomParameters[3]`へ4本の`float4`を渡せます。
Shaderパスと値は`.material.json`（version 2）およびシーンへ保存されます。
静的モデルは位置・法線・UVが共通Lit形式と互換な場合に対応します。
スキニング（ボーン）モデルも、Shaderに`VSSkinnedMain`があればカスタムShaderで描画します（エンジンがスキニング用に別途コンパイルし、専用の入力レイアウトを作ります）。

DirectXTK形式のModelRendererは、上書きが無効ならモデル内蔵マテリアルをそのまま使用します。
上書きを有効にした静的モデルが位置・法線・UVを持つ場合はLamaPon Litへ自動的に切り替わり、ベースカラー、粗さ、アルベド、法線マップ、Point／Spot Light、Directional ShadowがMeshRendererと同じ方法で適用されます。
Inspectorの「描画経路」で実際の経路を確認できます。

`VSSkinnedMain`を持たないShaderを指定したスキニングモデルや、法線／UVのないモデルはDirectXTK内蔵Effectへ安全にフォールバックします。
その場合も対応可能な色・粗さ・テクスチャ設定を内蔵Effectへ変換して適用します。
各ModelRendererは独立したEffectを生成するため、同じモデルを複数配置しても設定は漏れません。

## 3D Particle System

GameObjectへ`パーティクルシステム`を追加すると、カメラを向く3Dビルボード粒子をScene ViewとGame Viewへ描画できます。
Inspectorでは次を編集できます。

- 最大数、毎秒の生成数、寿命、初速、開始サイズ
- 寿命に沿ったサイズ倍率と開始／終了RGBAカラー
- 重力、再生時間、ループ、自動再生、エディターでのリアルタイムプレビュー
- Cone、Sphere、BoxのEmitter形状
- 加算合成／通常アルファ合成と任意のPNGテクスチャ

再生、停止、再開始、32個のBurstをInspectorから試せます。
通常アルファ合成ではカメラから遠い順に粒子を描画し、加算合成では発光エフェクト向けの高速な描画を行います。
Scene／Prefab保存、GameObject複製、アセットの名前変更・移動・削除時の参照追従にも対応します。
サンプルSceneの`発光パーティクルサンプル`には、透過済みの`textures/particle-glow.png`を使った青いエネルギー噴出を配置しています。

## ビルボード（画像をカメラへ向ける）

3D空間に置いた画像を常にカメラへ向けたいときは、`ビルボード`コンポーネント（コンポーネントを追加 → Animation）を付けます。
木・草、頭上のHPバー、光の玉、アイテムのアイコンなどがこれです。

画像はMesh RendererのPlaneにテクスチャを貼って作ります。

```cpp
auto& iconObject = scene.CreateGameObject("Icon");
iconObject.AddComponent<LamaPon::MeshRendererComponent>(
    LamaPon::PrimitiveShape::Plane,
    DirectX::XMFLOAT4{ 1.0f, 1.0f, 1.0f, 1.0f },
    "textures/icon.png");
iconObject.AddComponent<LamaPon::BillboardComponent>();
```

ビルボードには大きく**2種類**あり、違いが出るのは画面の端です。

| | 向き方 | 端での見え方 |
|---|---|---|
| **カメラの位置を向く** | 板ごとにカメラの座標へ向く | 端の板がこちらへ振り向くように回って見える |
| **画面と平行にする** | カメラの向きに合わせる（全部同じ向き） | どこにあっても同じ向き・同じ形。歪まない |

板状の絵は**画面と平行**（既定）が自然です。
球状の光のように「本当に立体である」ものは**位置を向く**方が正しく見えます。

**3D空間にUIを出すときは必ず画面と平行**にしてください。
頭上の名前、ダメージ表示、「調べる」のプロンプトなどは文字が読めることが最優先です。
位置を向く方式だと画面の端で板が振り向くため、文字が斜めに歪んで読みにくくなります。

- **向け方**（それぞれに「立ったまま」版があります）
  - `ScreenAligned`（既定）— 画面と平行。全部が同じ向きになります
  - `FaceCameraPosition` — カメラの座標を向きます
  - `UprightScreenAligned` — 立ったまま、画面の向きに合わせます。並べた
  草がすべて同じ向きになるので列が揃って見えます
  - `UprightFaceCameraPosition` — 立ったまま、カメラの座標を向きます。
  1本の木・頭上のHPバーはこちらです
  - `LookAtPosition` — カメラではなく指定したワールド座標を向きます
- **向ける面** — Mesh RendererのPlaneは面が真上（+Y）を向いているので、
  画像を貼る用途では既定の`Up`のままで構いません。
  正面が+Zのモデルを向けたいときは`Forward`にします
- 回転だけを毎フレーム上書きします（位置と大きさは触りません）。書くのは
  全コンポーネントのUpdateが終わった後（LateUpdate）なので、カメラをスクリプトで動かしていても1フレーム遅れません
- 親がいても大丈夫です。親の回転を打ち消したローカル回転を入れるので、
  親ごと回してもカメラを向いたままになります
- 向くのは**メインカメラ**で、**再生中だけ**です。エディターのシーンビューは
  自分のカメラで見ているため、止めているあいだは付けた向きのまま編集できます

パーティクルの粒はこのコンポーネントを付けなくても常にカメラを向きます（[3D Particle System](#3d-particle-system)のBillboardモード）。

## LODと描画カリング

遠距離用の軽量モデルは、それぞれ別の子GameObjectへModelRendererまたはMeshRendererとして配置し、親へ`LOD Group`を追加します。
InspectorでLODごとの最大距離と表示対象GameObject、完全に非表示にする距離を設定できます。

```cpp
auto& group = scene.CreateGameObject("Building LOD");
auto& high = scene.CreateGameObject("Building High");
auto& low = scene.CreateGameObject("Building Low");
high.SetParent(&group);
low.SetParent(&group);

group.AddComponent<LamaPon::LODGroupComponent>(
    std::vector<LamaPon::LODLevel>{
        { 25.0f, high.Id() },
        { 80.0f, low.Id() }
    },
    160.0f);
```

3D描画では次の順番で表示対象を絞り込みます。

1. カメラ距離からLODを1つ選択
2. Frustum Cullingでカメラの視錐台外を除外
3. 32×18の保守的な深度グリッドで、手前の不透明モデルに完全に隠れた物体を除外

OcclusionはGPU Query待ちを発生させない軽量なCPU方式です。
Box／Capsule／Sphere Colliderがある場合はそのBoundsを使い、それ以外はTransformされた単位Boundsを使います。
正確なカリング範囲が必要な大型モデルにはColliderを追加してください。
ワイヤーフレームModelRendererは遮蔽物として扱いません。

Inspectorの「シーン環境 → 描画カリング」で各機能のON/OFFと、総Renderer数、表示数、LOD／視錐台／遮蔽で除外された数を確認できます。
設定はSceneへ保存されます。

オブジェクト単位の例外は「描画カリング」コンポーネントで指定します（「コンポーネントを追加 → Rendering → 描画カリング」）。

- **カメラ外でも描画** — 視錐台・遮蔽カリングの対象から外し、常に描画します。
  広い地形や背景向けです
- **カリング余白** — 視錐台カリングの境界をワールド単位で広げます。頂点
  シェーダーで揺らす草木など、Boundsより大きく見えるものの消え際を防ぎます

コンポーネントが付いていないオブジェクトは通常どおりカリングされます。
旧形式のシーンにある同等の設定は、読み込み時にこのコンポーネントへ変換されます。

## ベイクした間接光（GI・照度ボリューム）

直接光だけの絵は、影の中が一様に暗くなります。
実際は光が壁や床ではね返って回り込むので、赤い壁のそばの床はほんのり赤くなります。
「シーン環境 → ベイクした間接光（GI）」はこれを事前計算（ベイク）で再現します。

1. **範囲の中心と大きさ**でシーンを覆う箱を決めます
2. **格子の分割数**を決めます（8×4×8程度から。多いほど細かいが遅い）
3. **間接光をベイク**を押します。進捗バーが出て、毎フレーム数点ずつ
  進みます（エディターは固まりません）

仕組みは、格子の各点で周囲の光を焼いて「場所ごとに違う環境光」を作るライトプローブ方式です。

- **動くオブジェクトにも効きます。** その場所の環境光を拾うだけなので、
  キャラクターが赤い壁のそばを通ると壁の色を反映します
- **ベイクは自動では走りません。** 物や光を動かしたら押し直して
  ください。
  結果はシーンファイルへ一緒に保存されます（8×4×8で約8KBと小さい）
- 間接光の**影はぼやけます**（格子の密度が解像度です）。くっきりした
  間接影が欲しい場面では格子を増やしてください
- 範囲の箱の外ではフラットな環境光へ滑らかに戻ります
- **強さ**はベイクし直さずに効きます
- 自作Shaderには効きません（標準Litシェーダーの環境光が対象です）

## リフレクションプローブ（ローカルの環境反射）

SkyboxのIBLはシーン全体で1つなので、屋内の金属が屋外の空を映してしまいます。
「リフレクションプローブ」コンポーネント（コンポーネントを追加 → Rendering）を置くと、その位置から見たシーンをキューブマップへ焼き、**中心がプローブの影響範囲に入っているオブジェクト**の反射と環境光がそれに置き換わります。

- **影響範囲** — 半径（ワールド単位）
- **強さ** — SkyのIBL強度と同じ扱いです
- **混ぜ始める距離** — 隣のプローブと混ぜ始める厚み。0のままだと境界で
  切り替わります（詳しくは下の「プローブのブレンド」）

ベイクはシーン読み込み後に自動で1回走ります。
物を動かしたらInspectorの「ベイクし直す」を押してください。

ベイク結果は`%LOCALAPPDATA%\LamaPon\environment-cache`へ自動保存され、次に同じシーンを開いたときは再ベイクせずに復元されます（シーンを開くたびの6面描画＋畳み込みが消えます）。
プローブを動かす・シーンのパスが変わると別物として扱われ、普通のベイクへ落ちます。
**シーンの中身を変えた場合は自動では検知できない**ので、映り込みが古いと感じたら「ベイクし直す」を押してください（保存も更新されます）。
実行中にスクリプトで作ったプローブは保存・復元の対象外です。

- 焼くのはポスト処理前のHDRリニアの絵です（IBLとして正しい値）
- 金属・低粗さのマテリアルほど効果がはっきり出ます。鏡面の球を
  プローブの中心に置くと、周囲がそのまま映り込みます
- ベイク中はプローブ自身の結果を使いません（プローブがプローブを
  映す循環を防ぐため）

### プローブのブレンド（境界で映り込みが飛ぶのを防ぐ）

プローブが1個だけのときは、範囲に入っているものがそのまま使われます。
複数が重なっている場所では**影響が一番大きいものと2番目**を混ぜます。

混ぜる比率は「混ぜ始める距離」から決まります。
0のままだと混ぜず、境界をまたいだ瞬間に映り込みが切り替わります（部屋を移動すると鏡面がパッと変わって目立ちます）。
値を入れると、範囲の縁からその厚みのあいだで少しずつ隣へ移ります。

```cpp
// 隣の部屋のプローブと3mかけて混ぜる
probe.SetBlendDistance(3.0f);
```

- 混ぜるのは**2個まで**です。3個以上が重なっている場所では、影響の
  大きい2つが選ばれます
- 反射の向きはプローブごとに**自分の箱**で補正します。別の形の部屋を
  またぐときも、それぞれの壁が正しい距離で映ります
- 強さも比率で混ざるので、明るさの違うプローブをまたいでも飛びません
- **すべてのプローブが0のままなら、絵は1バイトも変わりません。**
  既存のシーンに影響を出さないため、既定値は0にしています

### ボックス射影（部屋の形に合わせる）

キューブマップは本来「無限に遠い景色」として引かれるので、そのままだと床や壁がカメラの動きについてこず、狭い部屋の中では反射が滑って見えます。

Inspectorの「箱の大きさ（半径）」に部屋の半径（中心からの距離。
XYZそれぞれ）を入れると、反射の向きをその箱との交点へ補正します。
壁が正しい距離に映るので、鏡面の床に部屋がぴたりと収まります。

```cpp
auto& probe = roomObject.AddComponent<LamaPon::ReflectionProbeComponent>(
    20.0f,   // 影響範囲
    1.0f);   // 強さ
// 10m × 6m × 8m の部屋なら、半径は 5 / 3 / 4。
probe.SetBoxExtents({ 5.0f, 3.0f, 4.0f });
```

- **3軸すべてに正の値**を入れたときだけ有効になります。0を含んでいると
  従来どおり無限遠として扱います（既存のシーンの見た目は変わりません）
- 箱の中心はプローブの位置です。部屋の中心にプローブを置いてください
- 屋外や広い空間では不要です。無限遠のままのほうが自然に見えます

## SSAO（遮蔽による陰り）

物が接している隙間や角を暗くして、接地感を出します。
Inspectorの「シーン環境 → SSAO（遮蔽による陰り）」で有効化し、陰りを探す距離と濃さを調整します。

```cpp
auto occlusion = scene.AmbientOcclusion();
occlusion.enabled = true;
occlusion.radius = 0.5f;    // 陰りを探す距離（ワールド単位）
occlusion.strength = 0.6f;  // 濃さ（0～1）
scene.SetAmbientOcclusionSettings(occlusion);
```

- **深度バッファだけ**から計算します。法線バッファを持たない前方
  レンダリングでも動くよう、法線は上下左右の深度から再構成しています（追加のGバッファは作りません）。
  軸ごとに段差の小さい側を選ぶので、曲面でも輪郭沿いでも破綻しません。
- **半解像度で計算し、深度を見るブラーをかけます。** AOは低周波なので
  半分の解像度で足りて、計算量は1/4になります。
  ブラーが深度の段差を越えないため、手前の物の縁へ陰りが漏れることもありません。
- **環境光／IBL項だけを暗くします。** ライティングより前に深度だけの
  プリパスを走らせて遮蔽を用意し、Litシェーダーが環境光の項に対して掛けます。
  直接光や影の中は暗くならないので、影と陰りが重なって「汚れ」に見えることがありません。
  - 環境光の強度が0のシーンではSSAOの効果もゼロになります（掛ける先が
  無いため）。
  暗いシーンで効かないと感じたら、環境光かIBLの強度を上げてください。
  - プリパスはSSAOが有効なときだけ走ります。使わない構成では
  ジオメトリを2回描くコストがかかりません。
- 探索回数は品質プリセットで変わります（Low=8／Medium=12／High=16／
  Ultra=24）。
  多いほど滑らかですが重くなります。
  Customではプロジェクト設定から個別に指定できます。
- 品質設定の「SSAO（遮蔽による陰り）」でも有効である必要があります
  （Bloomと同じ扱い。
  プリセットではHigh以上でオン）。
  Low／Mediumではシーン側で有効にしていても描画しません。
- 自作Shaderのオブジェクトは、Shader側でSSAOを読む必要があります
  （[Shader](shaders.md)の「SSAOを受け取る」を参照）。
  読んでいない自作Shaderには陰りがかかりません。
  `LamaPonLit.hlsl`をそのまま使うMeshRenderer／ModelRendererは何もしなくてもかかります。
- 半径は小さめ（0.3～0.8m程度）が輪郭のはっきりした陰りになります。
  大きくするとぼんやり広がります。
- 距離が離れるほど画面上の探索範囲が小さくなるため、遠景の負荷は
  自然に下がります。

## TAA（時間的アンチエイリアス）

輪郭のギザギザを消します。
Inspectorの「シーン環境 →TAA（時間的アンチエイリアス）」で有効にします。

```cpp
auto temporal = scene.TemporalAntiAliasing();
temporal.enabled = true;
temporal.historyWeight = 0.9f;    // 前フレームを残す比率
temporal.jitterScale = 1.0f;      // ずらす量（ピクセル）
temporal.clampTolerance = 1.0f;   // 履歴を許す幅
scene.SetTemporalAntiAliasingSettings(temporal);
```

毎フレーム射影を**サブピクセルだけずらして**描き、前フレームの結果と混ぜます。
1枚のなかで平均を取るMSAAと違って時間をかけて平均するので安く、輪郭だけでなくテクスチャのちらつきにも効きます。
ずらし方はHalton列（基数2と3）で、8枚で1周します。
乱数だと同じ場所に固まる回があり、そのフレームだけ効かずにちらついて見えるためです。

- **前フレームをどこから読むか**は、深度からワールド座標を戻して前
  フレームの行列で射影し直して求めます（再投影）。
  カメラが動いても同じ場所を見続けられます
- **物体ごとの速度は持っていません。** そのため速く動く物の上では再投影が
  外れます。
  今のフレームの近傍9マスから色の範囲を作り、履歴をその範囲へ押し込むことで（近傍クランプ）残像を抑えています。
  **履歴を許す幅**を下げるとにじみが減り、上げるとギザギザ取りが強くなります
- **前フレームを残す比率**を上げるほど滑らかになりますが、動きに対して
  眠くなります。
  0.9前後が目安です
- **FXAAと二重にかけないでください。** どちらも輪郭を平すので、両方
  有効だと輪郭がぼやけます。
  TAAを使うならグラフィック品質のFXAAは切ってください
- ポスト処理の**一番先**にかけます。Bloomの後で混ぜると、前フレームの
  Bloomがさらに滲んで輪郭が二重になります
- リフレクションプローブのベイク中はずらしません（キューブに揺れが
  焼き付くため）
- 履歴と前フレームの行列は**ビューごと**に持ちます。エディターは
  シーンビューとゲームビューを同じフレームで描くため、共有すると互いを踏み合って再投影が壊れます
- SSRが読む「前フレームのカラー」はTAAで混ぜる**前**の絵です。混ぜた後を
  読ませると、TAAの履歴が反射経由でさらに積算されて像が流れます

## SSR（画面空間反射）

濡れた床、磨いた金属、水面に周りの景色を映します。
Inspectorの「シーン環境 → SSR（画面空間反射）」で有効にします。

```cpp
auto reflection = scene.ScreenSpaceReflection();
reflection.enabled = true;
reflection.intensity = 1.0f;         // 反射の強さ
reflection.maximumDistance = 12.0f;  // 映る距離（ワールド単位）
reflection.stepCount = 48;           // レイの反復の上限
reflection.thickness = 1.2f;         // 物の厚みの見積もり
reflection.roughnessCutoff = 0.45f;  // これより粗い面には掛けない
scene.SetScreenSpaceReflectionSettings(reflection);
```

**映るのは画面に写っているものだけです。** 画面の外にあるもの、物の裏側、カメラの後ろは情報が無いので映せません。
足りない分は[リフレクションプローブ](#リフレクションプローブローカルの環境反射)やSkyのIBLへ**滑らかに戻します**。
つまりSSRは環境反射を置き換えるものではなく、**近くのものだけ精度を上げる足し算**です。

### 映せない場所は自動で弱まります（設定は要りません）

「画面空間には情報が無い」場所は、エンジンが4つの条件で信頼度を0へ落として環境反射へ譲ります。
**どれも固定の値で、設定項目にはしていません。** 正解が1つに決まる補正なので、設定項目にはしていません。
画面端フェードと距離フェードを使います。

| 弱める条件 | 何を防ぐか |
|---|---|
| 画面の縁に近い（縁から8%） | 反射が画面の形に四角く切り取られて見えるのを防ぎます。**今のフレームと前フレームの両方**で見ます |
| 最大距離の近くまで進んだ（最後の1/4） | 最大距離のところで急に途切れると、カメラが少し動くだけで反射が現れたり消えたりします（ポッピング） |
| 反射がカメラへ向かっている | この向きは物の**裏側**が映るべきところですが、画面には手前の面しか写っていません。原理的に正しくできないので譲ります |
| 粗さが上限に近い | ぼやけた反射は1本のレイで表せません |

**距離フェードは「全区間を通して薄くする」やり方は採っていません。** それをすると、すぐ隣のものの映り込みまで薄くなって、いちばん見せたい足元の反射が弱くなります。
最後の1/4だけで落とします。

**レベル設計で避ける必要はありません。** これらはエンジン側の仕事です。
一方で「画面に写っていないものは映らない」という原理そのものは変えられないので、**大事な映り込みは画面内に入れる**（あるいはリフレクションプローブを置く）のは作る人の判断になります。

- **粗さ**が`roughnessCutoff`より小さい面にだけ掛かります。ざらざらした面の
  反射はぼやけていて、1本のレイでは表せないためです。
  鏡のような床を作りたいときは、マテリアルの粗さを0.05程度まで下げてください
- **物の厚み**は当たり判定の許容幅です。レイが物の**側面から**入った歩は、
  画面空間では「その物の裏を通っただけかもしれない」と区別が付きません。
  どこまでを裏と見なすかがこの値です。
  小さすぎると反射が途中で水平に切れ、大きすぎると物の裏の床にも映り込みます。
  既定の**1.2m**は人間サイズの物を想定しています。手すりや板のような
  薄い物が多い場面では、プレビューを見ながら下げてください。小さすぎると
  反射が途中で切れ、大きすぎると物体の裏側まで反射へ含まれます
- 計算はLitシェーダーの中で行います。シェーダーが持っている**正確な法線**
  （ノーマルマップ適用済み）をそのまま使えるので、法線バッファを別に持つ必要がありません
- 色は**前フレームのHDR**を読みます。今描いている絵は完成していないため
  読めないからです。
  当たった点は前フレームの画面座標へ**再投影**するので、カメラが動いても映り込みの位置はずれません
- 深度はプリパスの結果を**コピーしたもの**を読みます。Litパス中は深度が
  書き込み先として刺さっているため、同じリソースをシェーダーから読むことはできません（D3D11の制約）。
  有効なときだけコピーが走ります
- 有効にした直後の1枚は前フレームが無いので映りません（2枚目から効きます）
- SSAOと同じく、自作Shaderのオブジェクトは自分で読む必要があります
  （`LamaPonLit.hlsl`の`EvaluateScreenSpaceReflection`が実装です）
- **レイトレーシングによる反射は現状のD3D11では足せません。** DXRはD3D12
  専用で、DirectX 12対応が前提になります。

### レイの進め方（Hi-Z）

レイは**画面空間のHi-Zトラバーサル**で進めます。
深度バッファから「距離のminミップピラミッド」（各ミップが、その区画で最も手前の距離）を毎フレーム作ります。

- 「区画の最も手前より、レイの区間全体が手前」なら、その区画に当たりは
  存在しないので**区画ごと飛ばして**1段粗いミップへ上がります
- またぐかもしれないなら、進まずに1段細かいミップへ下ります
- 最細ミップ（＝1画素）でまたいだら、その区間を二分で詰めます

何も無い空間を大股で越えられるので、歩数は「画面の距離ぶん」ではなく**およそlog2(距離)**で済みます。
1画素ずつのDDAは上限128歩＝128画素で頭打ちでしたが、Hi-Zは既定の48反復で画面の端から端まで届きます。

`stepCount`は**反復の上限**です。
検証シーンでは48以上に増やしても結果が1も変わりません（予算が足りていれば、余りは使われないだけです）。
逆に床すれすれを長く這う映り込みは1画素に1反復を使うので、そこで途中で切れるときだけ増やしてください。

ミップを上がるのは「面から2%以上の余裕があるとき」だけです。
すれすれを這っている間に上がっても、次の反復ですぐ戻されて往復に浪費するだけなためです（この余裕の判定は相対なので、近くでも遠くでも同じ感覚で効きます）。

判定は「点」ではなく**区間**で行います。
区画の入口と出口で挟んで面をまたいだかを見るので、面を飛び越して奥へ抜けることが原理的に起きません。
画面の外へ出るところで打ち切り、深度（ピラミッド）は**点で読みます**（バイリニアだと輪郭をまたいだところで「手前と奥の中間」という存在しない距離が出て、偽の当たりになります）。

## ボリュメトリックライト（光の筋）

空気中の塵に光が散る様子を描きます。
窓から差し込む光、木漏れ日、霧の中の逆光がこれです。
Inspectorの「シーン環境 → 光の筋（ボリュメトリック）」で有効にします。

```cpp
auto volumetric = scene.VolumetricLight();
volumetric.enabled = true;
volumetric.intensity = 0.35f;        // 筋の濃さ
volumetric.sampleCount = 32;         // レイのサンプル数
volumetric.maximumDistance = 24.0f;  // 届く距離（ワールド単位）
volumetric.scattering = 0.6f;        // 前方散乱（0～0.95）
scene.SetVolumetricLightSettings(volumetric);
```

- **影を有効にした平行光源（Directional Light）が必要です。** カメラから
  伸ばしたレイに沿って既存のカスケードシャドウを引き、「光が届いている区間」だけを積み上げます。
  影が無いと遮る物が分からないため、筋も出ません（品質設定で影を切っている場合も同じです）
- **筋の濃さ**は平行光源の強度に掛かります。太陽を明るくすれば筋も
  明るくなるので、この値は「空気の濃さ」として考えてください
- **前方散乱**を上げると、太陽の方を向いたときだけ強く光ります。0にすると
  全方向へ均一に散って「霧」に近い見た目になります
- **届く距離**は平行光源の「影の距離」（既定24m）までに抑えられます。
  影のカスケードが覆っていない範囲は遮る物が分からず、そのまま光として積まれて画面が白く霞むためです。
  もっと遠くまで筋を伸ばしたいときは、Directional Lightの影の距離を先に伸ばしてください
- **サンプル数**が少ないと縞（バンディング）が出ます。ピクセルごとに
  開始位置をずらしているので32程度でも実用になりますが、遅い環境では16まで落として距離を短くするほうが破綻しません
- ポスト処理の中では**Bloomより前・HDRのうち**にかけます。明るい筋が
  そのままBloomで滲み、トーンマップも通るため、後段でLDRへ足すより自然に馴染みます
- リフレクションプローブのベイク中はかけません（キューブマップに
  光の筋が焼き付くのを防ぐため）

## 被写界深度（DoF）

ピントの合った距離から離れたものをぼかします。
カメラで撮った写真のような奥行き、寄りの演出、背景を退かせたい会話シーンがこれです。
Inspectorの「シーン環境 → 被写界深度 (DoF)」で有効にします。

```cpp
auto depthOfField = scene.DepthOfField();
depthOfField.enabled = true;
depthOfField.focusDistance = 6.0f;   // ピントの合う距離（m）
depthOfField.focusRange = 2.0f;      // 完全に鋭い前後の幅（m）
depthOfField.blurStrength = 1.0f;    // ぼけの強さ
depthOfField.maximumRadius = 10.0f;  // ぼけ半径の上限（画素）
scene.SetDepthOfFieldSettings(depthOfField);
```

| 設定 | 効果 |
|---|---|
| ピントの合う距離 | ここにあるものが鋭く写ります。見せたい被写体までの距離を入れます |
| ピントの合う幅 | この帯の中は1画素もぼけません。0にすると焦点面ちょうどだけが鋭くなります |
| ぼけの強さ | 焦点面からのずれに掛かる倍率。絞りを開けたレンズに近づきます |
| ぼけ半径の上限 | 見た目と処理コストの上限（画素）。サンプル数は品質設定側です |

- **深度プリパスは要りません。** メインパスが書いた深度をそのまま読むので、
  SSAOやSSRを切っていても動きます
- **手前のぼけは奥へはみ出しますが、奥のぼけは手前へはみ出しません。**
  ピントの合った被写体の前にある枝は被写体に覆いかぶさる一方、奥の背景が鋭い輪郭の外へにじむと「霧をまとった切り抜き」に見えるため、そちら向きは抑えています
- **手前は急に、奥は緩やかにぼけます。** 薄レンズと同じ形（距離の逆数の差）を
  使っているためで、奥はどこまで行ってもぼけ半径の上限で飽和し、手前は距離が半分になるたびに倍で増えます。
  距離の差をそのまま使う実装ではこの非対称さが出ず、「奥だけ延々とぼける」不自然な絵になります
- **空はぼけます。** 空は無限遠なので、10mにピントを合わせたカメラで
  空がぼけるのと同じです。
  背景を鋭く残したいときはピントを遠くへ置きます
- **2D／UIには掛かりません。** SpriteとUIはポスト処理の後に描くためです
- ポスト処理の中では**Bloomより前・HDRのうち**にかけます。ぼけた絵に対して
  Bloomが滲むのが正しい順序で、逆にすると「ぼけているのに輪郭だけ光っている」絵になります
- **ぼかしは半解像度**で行い、合成だけフル解像度です。ぼけた絵に細部は
  残らないので解像度を落としても失うものがなく、計算量が1/4になります。
  合成をフル解像度で行うのは必須で、ピントが合っている面はここで元の絵から取り直します
- サンプル数はプロジェクトのグラフィック品質設定側です（Low=10、
  Medium=16、High=22、Ultra=32）。
  少ないとぼけが粒状になります
- プロジェクトのグラフィック品質設定でも有効である必要があります
  （High以上のプリセットで有効）。
  設定はシーンJSONの`environment.depthOfField`へ保存されます
- リフレクションプローブのベイク中はかけません（キューブマップにぼけが
  焼き付くと反射だけ二重にぼけるため）

## モーションブラー（カメラの動きによるブレ）

カメラが動いたぶんだけ絵を伸ばします。
カメラを振る、走る、乗り物に乗るときの勢いがこれです。
Inspectorの「シーン環境 → モーションブラー」で有効にします。

```cpp
auto motionBlur = scene.MotionBlur();
motionBlur.enabled = true;
motionBlur.intensity = 0.5f;      // ブレの強さ（シャッターの開き具合）
motionBlur.maximumRadius = 16.0f; // 伸ばす最大の長さ（画素）
scene.SetMotionBlurSettings(motionBlur);
```

- **カメラの動きだけが対象です。** 止まっているカメラの前を走るキャラクターは
  ブレません。
  物体ごとの速度（速度バッファ）を持つと自作ShaderがGBufferへ書けなくなるため、TAAと同じ理由で避けています
- **深度と前フレームの行列だけで動きます。** TAAの再投影とまったく同じ計算で
  「この画素が前フレームどこに写っていたか」を求め、その差に沿ってサンプルします。
  新しいバッファは要りません
- **ブレの強さ**は1.0で「前フレームから今フレームまでに動いたぶん」をそのまま
  伸ばします。
  0.5なら半分で、映画のシャッター（180度）に近い見た目です
- **伸ばす最大の長さ**は必ず必要です。上限を切らないとカメラを素早く振った
  ときに画面全体が溶けます。
  サンプル数は品質設定側なので、ここだけ広げるとブレが縞に分かれて見えます
- **走っても空はブレませんが、振り向くとブレます。** 無限遠に近い点はカメラの
  平行移動ではほとんど動かず、回転では大きく動くためで、式のうえで自動的にそうなります
- **カメラが動いていないフレームは何もしません**（半画素未満の移動は捨てます）。
  静止画がサンプルの丸め誤差でわずかに甘くなるのを防いでいます
- ポスト処理の中では**被写界深度の後・Bloomより前**です。光はレンズ（ぼけ）を
  通ってからセンサーへ届き、ブレはそのセンサーが開いている時間で起きるので、この順が実際の並びです
- プロジェクトのグラフィック品質設定でも有効である必要があります
  （High以上のプリセットで有効）。
  設定はシーンJSONの`environment.motionBlur`へ保存されます
- リフレクションプローブのベイク中はかけません

## 自動露出（明順応・暗順応）

画面の明るさを測って露出を上下させます。
暗い洞窟から外へ出たときに目が慣れていく、あの表現です。
Inspectorの「シーン環境 → 自動露出」で有効にします。

```cpp
auto autoExposure = scene.AutoExposure();
autoExposure.enabled = true;
autoExposure.keyValue = 0.18f;          // 目標の明るさ（中間グレー）
autoExposure.minimumLuminance = 0.02f;  // 測った明るさの下限
autoExposure.maximumLuminance = 8.0f;   // 上限
autoExposure.speedToBright = 3.0f;      // 明るい方へ慣れる速さ（1秒あたり）
autoExposure.speedToDark = 1.0f;        // 暗い方へ慣れる速さ
scene.SetAutoExposureSettings(autoExposure);
```

- **手動の露出はこの上に乗る「補正値」になります。** Color Gradingの露出は
  加算されるので、自動露出と同時に使えます。
- **トーンマッピングを切っていると効きません。** 露出はトーンマップのパスの
  中で掛かるためです。
  Inspectorにも注意書きが出ます
- **カラー調整のオン/オフには左右されません。** 露出はカメラの挙動であって
  色の作り込みではないので、「カラー調整を切ったら真っ白になった」という驚きを作らないようにしています
- **平均は対数（幾何平均）で取ります。** 線形の平均だと、画面の隅にある1個の
  明るい光源が平均を支配して、暗い部屋がもっと暗くなります。
  対数なら「何段明るいか」の平均になります
- **明るい方へは速く、暗い方へは遅く慣れます**（既定は明3.0 / 暗1.0）。本物の
  目も暗順応のほうが遅いためです。
  速さは1秒あたりで、フレームレートが変わっても同じ秒数で同じところまで慣れます
- **下限と上限は必ず入れてください。** 真っ暗なシーンで開けきると暗部のノイズ
  だけが持ち上がり、真っ白なシーンで絞りきると何も見えなくなります
- **測定はGPU、順応の計算はCPUです。** 1/4解像度へ輝度の対数を書き、ミップ
  生成で1x1まで平均し、その4バイトだけを**1フレーム遅れ**で読みます（同じフレームで読むとGPUの完了待ちで必ず止まります）。
  順応自体が時間をかける表現なので、1フレームの遅れは見えません
- **順応はビューごとに別です。** エディターのScene ViewとGame Viewは別々に
  慣れます。
  Inspectorには「測定中の明るさ」と「補正の段数」が出るので、効いているかどうかは数字で確かめられます
- 最初のフレームは順応させずに測った値をそのまま採ります（ゲーム開始直後に
  画面が勝手に明るくなったり暗くなったりする数秒を作らないため）
- プロジェクトのグラフィック品質設定でも有効である必要があります
  （High以上のプリセットで有効）。
  設定はシーンJSONの`environment.autoExposure`へ保存されます

## レンダーテクスチャ（ミニマップ・防犯カメラ）

Cameraの描画先を画面ではなくテクスチャにできます。
InspectorのCamera→「描画先（Render Texture）」に名前を入れ、同じ名前をSprite RendererまたはUI Imageの「Render Texture」に指定すると、そのカメラの映像が画面に出ます。
ミニマップ、防犯カメラ、装備プレビュー、ポータルはこれ1つで作れます。

```cpp
// 真上から見下ろすミニマップ用カメラ
auto& minimapObject = scene.CreateGameObject("Minimap Camera");
minimapObject.GetTransform().position = { 0.0f, 40.0f, 0.0f };
minimapObject.GetTransform().SetEulerAngles(
    { 1.5f, 0.0f, 0.0f });

auto& minimapCamera = minimapObject.AddComponent<LamaPon::CameraComponent>();
minimapCamera.SetTargetTexture("minimap");        // 描画先の名前
minimapCamera.SetTargetTextureSize(256, 256);     // 既定は512x512
minimapCamera.SetTargetClearColor({ 0.0f, 0.0f, 0.0f, 0.6f });

// 画面の隅に貼る
auto& hud = scene.CreateGameObject("Minimap HUD");
auto& sprite = hud.AddComponent<LamaPon::SpriteRendererComponent>(
    DirectX::XMFLOAT2{ 200.0f, 200.0f });
sprite.SetRenderTexture("minimap");               // カメラと同じ名前
```

UIに出す場合はUI Imageへ`SetRenderTexture("minimap")`を使います（Rect Transformでアンカー配置できます）。

決まりごと:

- **名前で結びます** — カメラ側の描画先名と表示側の名前が一致すれば繋がります。
  同じテクスチャを複数のSpriteやUI Imageから同時に表示できます。
- **2D／UIはテクスチャへ描かれません** — テクスチャを表示しているSprite自身が
  写り込む無限ループを防ぐためです。
  映るのは3Dだけです。
- **Bloom・トーンマッピング・FXAAは適用されます**（品質設定に従います）。
- **背景色のアルファを下げると半透明**になります。上のミニマップ例のように
  下地を透かせられます。
- **解像度は小さめが軽い**です。ミニマップなら256x256で十分です。
  1フレームに1回、カメラごとに描き直されます。
- **Scene Viewでも更新されます**（停止中でも絵が出ます）。
- Scene切り替えでテクスチャは破棄され、次のフレームで作り直されます。
- カメラ側の名前を空にすると、通常どおり画面へ描くカメラに戻ります。

## よくあるつまずき

- **ミニマップが真っ黒** — Camera側の描画先名とSprite側の名前が一致しているか、
  そのカメラが有効か（GameObjectごと無効になっていないか）を確認します。
  2D／UIはテクスチャに描かれないため、映すのは3Dオブジェクトだけです。
- **画面が暗い／真っ黒** — シーンにライトがあるか確認します（新規シーンには
  「太陽光」が自動で入りますが、削除すると環境光だけになります）。
- **影が出ない** — ライト側の影設定がONか、品質プリセットがLow
  （影無効）になっていないかを確認します。
- **モデルが表示されない** — 対応形式（.gltf/.glb/.fbx/.cmo等）か、
  ModelRendererへ割り当て済みかを確認します。
  Inspectorの「描画経路」で実際にどの経路で描かれているかも確認できます。
- **映り込みがそれっぽくならない** — プロシージャルSkyboxのままでは簡易的な
  環境光のみです。
  `.dds`キューブマップを設定するとIBL（粗さに正確な反射）が有効になります。
- **遠くの物が急に消える** — LOD Groupの非表示距離、またはカリング設定を
  確認します。
  「シーン環境 → 描画カリング」でどの段階で除外されたかが数字で分かります。
- **パーティクルが眩しすぎる／地味すぎる** — 加算合成（発光向け）と
  通常アルファ合成（煙など）の切り替えとBloomのしきい値を調整します。
